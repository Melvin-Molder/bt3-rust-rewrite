# BT3 Recomp

An original Rust implementation intended to read data from a user-provided copy of Dragon Ball Z: Budokai Tenkaichi 3. The repository contains no game assets or decompiled game code.

## Data-loading proof

The `bt3-data` crate reads the ISO9660 primary volume descriptor and root `SYSTEM.CNF`, then locates and interprets real game resources in the AFS archives. It converts the three loading-screen resources (global file IDs `0x3C1`–`0x3C3`) to in-memory RGBA textures and reads stage gameplay metadata from stage file `0x171`. Run its inspector from the workspace root:

```powershell
cargo run -p bt3-data --bin bt3-inspect
```

By default it reads `rom/Dragon Ball Z - Budokai Tenkaichi 3 (USA) (En,Ja).iso`; pass another ISO path as the first argument to override it. The ISO path reader resolves nested directories, and the AFS reader seeks directly to requested entries rather than loading the 1.46 GB archive. The global file-ID mapping, loading-screen behavior, stage layout, and coordinate transforms are grounded in the decomp sources listed below. Packed data, decoded resources, and RGBA textures stay in memory and are not extracted to disk.

Run the Bevy prototype with `cargo run -p bt3-game`; it accepts the ISO path as its first argument as well. By default it plays the boot pictures of `FirstRun_Main`: the six logos from menu archive `0x1DA`, at 60 Hz, with the original timing, fade colours and skip rules (Space / Enter or a gamepad's South / Start as pad 0 Cross / Start). The memory-card check before them is not ported yet. After them it plays the opening movie as `Movie_Run` does: `DATA/ZS3USOP.PSS` streamed from the ISO through `ffmpeg` (which must be on `PATH`) at one picture per two NTSC fields, with the `DATA/ZS3USOP.ADX` soundtrack decoded in Rust and played at the original's -12.9 dB; Start skips it with a half-second fade. Then it runs the title screen as `Title_Run(1)` does: the still picture for 300 frames, then the title movie (a FOD file, the game's converted Flash format) played by a port of the game's Flash player (`src/sys/flash.c`), with the scrolling clouds, the menu plates, the "Press START button" plate and the New Game / Continue menu (arrows or the d-pad move the cursor, with the original key repeat). The title music (`0x10B16`) loops at -12.9 dB, the announcer lines play at -1.6 dB, and both fade out by 12 dB a frame as the screen fades. `--title` starts there directly. Sound effects play as the game's sound driver plays them: the bank files (`0x14B`, `0x14C`) are read from the ISO, their SE sequences, timbres and ADPCM samples drive an emulated SPU2 (pitch, Gaussian interpolation, ADSR, volume and pan follow Sony's `modsesq2` / `modhsyn` modules from the disc and the psx-spx hardware notes). New Game opens the memory-card dialog of `McFlow_Start(3)` (ports of `src/sys/dialog.c`, `src/sys/memcard_flow.c` and the text printer `src/sys/font.c`, with both fonts of boot file 5); Left / Right move between Yes and No. No memory card is emulated, so the flow takes the game's "No memory card (PS2) inserted" path, and "Start a new game without saving?" → Yes leaves for the main menu. The main menu runs as `MainMenu_Run(2)` does (src/menu/main_menu.c, with the message and icon windows, the menu animation helpers and lip sync): the scrolling ring of mode plates with animated icons, the four guides blinking and talking, the greeting and per-item voice lines with their subtitles, Up / Down with the original key repeat, Cross to choose and Escape (or a gamepad's North) as Triangle to go back to the title, which then offers Continue. `--menu` starts there directly. Duel (main-menu item 3, progress mode 38) opens the Versus menu as `DuelMenu_Run(1)` does (src/menu/duel_menu.c): its music (`0x10B1B`), Vegeta and Nappa as talking guides, 1P vs COM / 1P vs 2P (greyed out without a second controller) / COM vs COM with the battle type and DP limit, and the battle settings with their value picker and "restore defaults" dialog; the choices and settings are kept for the next visit. 1P vs COM / COM vs COM with a single battle goes on to the character select as `CharSel_Run(2)` does (src/menu/char_select.c): the two character reels with forms, item-set and costume plates (costume counts from the character table of common file 4), portraits and stage pictures streamed from the ISO as the cursor moves, the stage reel with its cross-fading pictures and the music list, the save's default unlocks, and the VS animation; it ends by writing the battle setup. The battle then starts as `Battle_Main` does (src/battle/battle.c): `Battle_Load`'s loading screen runs (with `Load_RunBlocking`'s one-second fade-out once the files are read) while the two fighters' model files (`0x590 + chara * 10 + costume`), the stage file and the light ramp of common file 2 are read; the battle music (`0x10B16 + bgm`) starts, and every 30 Hz frame the fighters are drawn as `BtlObjDraw_DrawModel` and VU1 program 0 draw them: the model parts' VIF streams are walked into VU1 memory, each batch's triangle strip is transformed, lit (u = 0.5 + 0.5 · −L·n with the stage's light) and projected on the CPU with the battle view's matrices, and drawn by a shader that does the GS's work (perspective-correct STQ, the model texture, then the shading ramp looked up through the material's CLUT and subtracted with ALPHA_2 0x62). The view is side 0's fighter camera (`ChrCam_CalcLockOn`). Each fighter loops its idle motion (motion 0 of its motion file `0x598 + chara * 10`, BPE-packed, two frames per 30 Hz update as `BtlAnim_AdvanceLoop` steps it): the tracks are sampled as `BtlObjAnim_SamplePose` does (packed "smallest three" quaternions, slerp, rest translations), the motion flag table of common file 2 is applied, and the node matrices are built down the model's skeleton as `BtlObjPose_CalcMatrices` does, so every part is skinned between its node and its parent. The fighters stand at the stage's starting places, because their actions, the hair / cloth chains, face animation, stage geometry, intro camera and HUD are not ported yet. `--battle` starts there directly with characters 0 and 1 on stage 0. Not ported yet: the item panel of the character select, the team select, the rest of the battle, the other modes behind the main menu, and the attract battle; when a screen ends with those, the screen stays black. After the third idle timeout the title replays the opening movie, as the original does. `--screen 0`, `1` or `2` runs a loading screen instead, driven by the decomp-ported `Load_*` logic at 30 Hz; Space stands in for Cross (`PADG_CROSS`, game bit `0x200`).

## Sources and credit

- The crate-oriented separation of game/data concerns is informed by [gang-beasts-rust](https://github.com/muffinmxn/gang-beasts-rust) (MIT-licensed upstream project). No upstream source code or game data was copied.
- BT3 format research sources are listed in [bt3-format-research.md](bt3-format-research.md), including the BT3 community research archive, AFS tools, map MDL unpacker, animation tools, and PS2 executable decompilation.
- The global file-ID mapping and BPE loading-screen behavior are based on `C:\Users\User\.code\BT3-Decompiled\src\sys\file.c`, `src\sys\loading.c`, `src\sys\bpe.c`, and `include\sys\loading.h` (CC0-1.0 for decomp project contributions). The Rust decoder is an independent implementation; no decompiled source was copied.
- Stage file IDs, relative-offset units, gameplay metadata, and coordinate conversion are based on the decomp stage loader, relocation, and stage-data readers. The Rust reader is an independent, bounds-checked implementation.

The source and format references are credited for research only; their licenses remain with their respective projects. The game and its data remain the property of their rights holders.
